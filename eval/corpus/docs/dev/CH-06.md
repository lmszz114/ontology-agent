# 슬랙 대화 CH-06

2026-10-20 기록

김OO(라이브운영팀): 이벤트 보상 과지급 건 올라온 거 다들 봤죠? 회수 절차를 열어야 하나 싶어서 채널 팝니다.

이OO(고객지원팀): 문의가 몇 건 들어오긴 했어요. 근데 다들 "보상이 두 번 온 것 같다"는 말뿐이라 정확한 건 모르겠습니다.

박OO(개발팀): 일단 원인부터 확인해야 합니다. 절차를 열지 말지는 원인에 달려 있어요.

김OO(라이브운영팀): 기준이 어떻게 됐죠? 저는 과지급이면 무조건 여는 줄 알았는데.

박OO(개발팀): 아니요. 과지급인데 원인이 이벤트 설정 오류일 때, 그때 아이템·재화 회수와 제재 절차를 엽니다. 과지급이라는 사실만으로 열리는 건 아니에요.

김OO(라이브운영팀): 아, 그렇군요. 제가 잘못 알고 있었네요. 정정 감사합니다.

최OO(QA팀): 제 추측인데, 이벤트 툴에서 보상 수량을 잘못 넣은 거 아닐까요? 그럼 설정 오류 맞잖아요.

이OO(고객지원팀): 그럴 수도 있는데 아직 확인된 건 없죠. 추측으로 제재까지 가면 곤란합니다.

최OO(QA팀): 네 맞아요, 그냥 제 느낌이었습니다. 취소합니다 ㅎㅎ

정OO(개발팀): 다른 가능성도 생각해 보면, 우편함 쪽에서 뭔가 꼬였을 수도 있어요. 이벤트 툴이 우편함에 의존하는 구조니까요.

최OO(QA팀): 그럼 이벤트 툴 때문에 우편함이 문제가 된 거 아닌가요?

정OO(개발팀): 방향이 반대예요. 이벤트 툴이 우편함에 기대는 쪽이라, 우편함에 문제가 생기면 이벤트 툴에 영향이 가는 겁니다. 이번 건이 그쪽에서 시작됐는지는 저도 아직 모릅니다.

최OO(QA팀): 아 반대였구나. 헷갈렸네요. 정리해 주셔서 감사합니다.

박OO(개발팀): 그러니까 우편함 문제 때문이라면 설정 오류가 아니라서 회수·제재 절차 대상이 아닐 수도 있다는 거죠. 확인 전에는 단정하지 맙시다.

김OO(라이브운영팀): 그럼 이벤트 툴 설정 이력이랑 우편함 상태를 둘 다 먼저 보면 되겠네요. 확인되기 전에는 절차를 열지 않는 걸로 하겠습니다.

이OO(고객지원팀): 동의합니다. 문의 주신 분들께는 확인 중이라고만 안내해 둘게요.

정OO(개발팀): 확인되면 이 채널에 바로 공유하겠습니다.

최OO(QA팀): 근데 오늘 점심 뭐 드세요? 저는 이 얘기 하다 보니 우편함 대신 위장이 비었어요.

김OO(라이브운영팀): 과지급 말고 급식 얘기네요 ㅋㅋ 저는 김치찌개 갑니다.

박OO(개발팀): 저도 찌개요. 회수 절차가 필요하면 점심 먹고 열죠.

이OO(고객지원팀): 순서가 이상한데 일단 찬성입니다.
