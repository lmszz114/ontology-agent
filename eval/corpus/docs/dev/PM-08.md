# 장애 회고: 경매장 서버 배포 뒤 등록 실패가 이어진 사건

작성: 서버개발팀 / 2026-10-15

## 사건 개요

경매장에서 등록 실패가 이어지는 장애가 발생했다. 이런 증상이 나타날 때 가장 먼저 의심하는 원인 후보는 경매장 서버 오류이고, 지금까지 경험상 가능성도 높은 편이다. 이번에도 이 후보부터 확인했다.

## 타임라인

증상이 보고되자 경매장 서버 오류를 1순위로 두고 두 가지 조회를 진행했다. 먼저 서버 오류 로그를 살폈고, 이어서 배포 이력을 대조했다. 두 조회 결과가 같은 방향을 가리켜 경매장 서버 오류로 판단했다. 이후 긴급 공지, 긴급 점검, 롤백, 원인 수정과 반영을 차례로 진행했다.

## 확인한 근거

근거는 두 가지다. 하나는 서버 오류 로그 조회 결과로, 경매장에서 이번 증상과 관련된 오류 로그가 확인되었다. 다른 하나는 배포 이력 조회 결과로, 증상이 시작되기 전에 경매장 배포 이력이 남아 있었다. 배포가 먼저 있었고 그 뒤에 증상이 시작되었으며 같은 곳에서 오류 로그도 나왔으니, 경매장 서버 오류라는 판단에 무리가 없었다.

경매장은 월드 서버에 의존하는 구조라서 월드 서버에 문제가 생기면 경매장에도 영향이 간다. 그래서 등록 실패 같은 증상이 보이면 월드 서버 쪽 가능성도 염두에 두어야 한다.

## 원인

원인은 경매장 서버 오류다. 이는 경매장의 로직 쪽 문제에 해당한다. 증상은 경매장에서 나타났고, 로직 변경이 담긴 배포 뒤에 시작되었다.

## 담당

경매장의 로직은 서버개발팀이 맡고 있다. 그래서 이번 건의 원인 확인과 수정도 서버개발팀이 주도했다.

## 조치

경매장 서버 오류가 원인일 때 여는 절차를 순서대로 진행했다.

- 긴급 공지: 이용자에게 장애 사실을 알렸다.
- 긴급 점검: 경매장을 점검 상태로 두고 작업했다.
- 롤백: 문제가 된 배포를 되돌렸다.
- 원인 수정과 반영: 로직의 문제를 고쳐 다시 반영했다.

## 재발 방지

배포 직후에는 경매장의 서버 오류 로그에 증상과 관련된 항목이 생기는지 서버개발팀이 먼저 살펴보기로 했다. 등록 실패가 다시 보이면 이번처럼 서버 오류 로그와 배포 이력을 함께 조회해 원인을 좁힌다. 월드 서버 의존 관계도 함께 확인 항목으로 둔다. 원인이 경매장 서버 오류로 확인되면 같은 네 가지 절차를 곧바로 연다.
