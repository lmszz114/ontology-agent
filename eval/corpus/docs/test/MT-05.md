## 안건

1. DB 운영 현황 점검
2. 서버 인프라 점검 일정이 DB에 주는 영향
3. 장애 발생 시 연락 체계 정리

## 논의

DB 운영은 현재 서버개발팀이 맡고 있다. 서버개발팀은 최근 몇 주간 DB 응답 속도에 눈에 띄는 변동은 없었다고 보고했다. 다만 DB가 서버 인프라에 의존하는 구조라서, 인프라 쪽에 문제가 생기면 DB도 곧바로 영향을 받는다는 점을 다시 확인했다. 지난 점검 때처럼 인프라 작업이 겹치는 시간대에는 DB 쪽 지표를 더 자주 봐야 한다는 의견이 나왔다.

운영팀은 점검 공지가 나가기 전에 DB 영향 범위를 먼저 알려 주면 이용자 안내문을 쓰기가 훨씬 수월하다고 했다. QA팀은 점검이 끝난 뒤 DB에 저장된 캐릭터와 아이템 데이터가 정상인지 확인하는 절차를 따로 두자고 제안했다.

장애 연락 체계와 관련해서는 DB 이상을 처음 발견한 팀이 누구든 우선 서버개발팀에 알리고, 서버개발팀이 원인을 확인한 뒤 운영팀에 전달하는 흐름으로 의견이 모였다.

## 결정

- 인프라 점검 일정은 확정 즉시 서버개발팀이 운영팀과 QA팀에 공유한다.
- 점검 중에는 DB 지표를 평소보다 짧은 간격으로 확인한다.
- 점검 종료 후 QA팀이 DB 데이터 정합성을 확인한다.
- DB 이상 징후는 서버개발팀을 1차 연락처로 한다.

## 후속 작업

- 서버개발팀: 점검 일정 공유 양식 작성, DB 지표 확인 간격 정리
- 운영팀: 점검 공지 문안에 DB 영향 범위 항목 추가
- QA팀: 점검 후 데이터 확인 항목 목록 작성
- 다음 회의에서 세 팀의 결과물을 함께 검토한다.
