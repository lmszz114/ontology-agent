# 런북: 패치 배포 (2024년판)

작성: 클라이언트개발팀 / 작성일: 2024-03-02

## 언제 쓰는가

이 문서는 정기 점검 후 신규 패치를 라이브에 내보낼 때, 그리고 배포 도중 이상 징후가 보여 대응 순서를 확인해야 할 때 참고한다. 배포 실행은 클라이언트개발팀이 맡고 있으므로 당일 실행 담당자는 이 문서를 처음부터 끝까지 읽고 시작한다.

## 알아둘 구조

게임 클라이언트는 패치 서버에 의존한다. 유저는 클라이언트를 켜기 전에 런처로 최신 파일을 받아야 하므로, 패치 서버에 문제가 생기면 그 영향이 곧바로 클라이언트로 번진다. 파일을 내려받지 못하는 정도에서 끝나지 않고 접속 자체가 막히는 경우도 있다. 따라서 배포 작업의 성패는 패치 서버의 상태에 달려 있다고 생각하고 움직인다.

## 단계

1. 배포 예정 빌드의 번호와 파일 목록을 확인하고, 사내 테스트 환경에서 마지막으로 실행해 본 결과를 팀 채널에 남긴다.
2. 배포 직전에 패치 서버의 응답 상태를 점검한다. 응답이 느리거나 불안정하면 배포를 시작하지 않고 팀장에게 보고한다.
3. 빌드를 패치 서버에 올린 뒤, 테스트 계정으로 런처를 열어 새 버전이 내려받아지는지 확인한다.
4. 내려받은 클라이언트가 정상 실행되고 로그인까지 되는지 확인한다.
5. 이상이 없으면 공지 담당자에게 배포 완료를 알린다.

## 주의 사항

- 패치 서버가 불안정한 상태에서 배포를 강행하지 않는다. 문제가 생기면 모든 유저의 클라이언트가 함께 영향을 받는다.
- 3단계와 4단계 사이에 오류가 나오면 즉시 작업을 멈추고, 올린 빌드를 이전 버전으로 되돌릴 수 있는지부터 판단한다.
- 작업 내용은 단계마다 팀 채널에 기록한다. 나중에 원인을 추적할 때 이 기록이 가장 먼저 쓰인다.
- 판단이 어려우면 혼자 결정하지 말고 팀장에게 연락한다.
