# 온톨로지 장애 진단 에이전트

라이브 운영 경험을 바탕으로 MMORPG 운영 조직을 가정하고, 조직, 시스템, 절차를 온톨로지로 설계해 장애 제보의 원인과 담당 팀을 찾는 에이전트를 만드는 프로젝트입니다. 같은 지식을 통째로 넣는 방식, 문서 검색(RAG), 온톨로지를 같은 조건에서 비교할 예정입니다.

## 현재 상태

- 개발 중입니다. 설계를 마쳤고 첫 번째 구현 단계(M1)를 시작하기 전입니다.
- 아직 동작하는 기능과 평가 결과는 없습니다.
- 이 README는 임시본이며, 개발이 끝나면 실행 방법과 평가 결과를 포함해 다시 작성합니다.

## 만들 예정인 것

- 온톨로지: 가상 MMORPG 운영 조직의 팀, 역할, 시스템, 증상, 원인, 절차를 담은 그래프
- 진단 에이전트: 여러 채널로 들어온 장애 제보를 묶고, 원인 후보와 담당 팀을 근거와 함께 제시
- 승인 게이트: 저위험 조치는 자동 실행하고 고위험 조치는 사람의 승인을 요청 (대응 조치 실행은 시뮬레이션)
- 추출 에이전트: 장애 회고, 런북 같은 가상 현장 문서에서 지식 후보를 추출하고, 사람이 검수한 것만 온톨로지에 반영
- 비교 평가: 지식 전체 입력, 문서 검색(RAG), 온톨로지 방식을 같은 시나리오로 비교하고 결과를 평가 리포트로 공개

조직, 시스템, 문서, 시나리오는 모두 가정해서 만든 가상 데이터입니다.

## 사용 예정 기술

| 영역 | 기술 |
| --- | --- |
| 언어 | Python |
| 에이전트 프레임워크 | LangGraph |
| LLM | Claude API (기본 Claude Haiku 5.5, 비교용 Claude Sonnet 5.5) |
| 임베딩, 리랭크 | Voyage AI (voyage-4, rerank-3) |
| 그래프 DB, 벡터 검색 | Neo4j (그래프와 벡터 인덱스) |
| 도구 연결 | MCP 서버 |
| 실행 기록, 비용 기록 | Langfuse |
| 접수, 승인 | Jira Service Management, 슬랙 |
| 검수 화면 | Streamlit |
| 평가 리포트 | 정적 HTML, GitHub Pages |
| 회귀 테스트 | GitHub Actions |
| 실행 환경 | Docker Compose |

구현하면서 바뀔 수 있습니다.
